<threat_model>
## Trust boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions → secrets / OIDC | Workflows access `GITHUB_TOKEN`, npm OIDC, optional `ANTHROPIC_API_KEY` in e2e dispatch. |
| Fork PRs from untrusted contributors | `GITHUB_TOKEN` permissions must stay minimal on `pull_request`. |

## STRIDE register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-3-01 | Spoofing | workflow triggers | mitigate | Restrict `pull_request` to `main`; avoid `pull_request_target` unless required (upstream does not). |
| T-3-02 | Tampering | npm publish jobs | mitigate | Keep environment-gated publish jobs; `id-token` only on publish. |
| T-3-03 | Repudiation | release tags | mitigate | Preserve upstream tag push behavior until semantic-release supersedes (document in FORK_DIFF). |
| T-3-04 | Information disclosure | secrets in logs | mitigate | Reference secrets only in `env:`; never `echo` tokens; e2e uses repo secrets by name only. |
| T-3-05 | Denial of service | malicious PR resource burn | accept | Same concurrency cancel-in-progress as upstream `pr.yml`. |
| T-3-06 | Elevation | overly broad `permissions` | mitigate | Mirror upstream least-privilege split across jobs. |
</threat_model>
