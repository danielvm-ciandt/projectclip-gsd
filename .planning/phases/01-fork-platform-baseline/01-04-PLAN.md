<threat_model>
## Trust boundaries

| Boundary | Description |
|----------|-------------|
| semantic-release → GitHub API | Uses `GITHUB_TOKEN` / `GH_TOKEN` for releases and tags in non-dry-run future. |
| npm / OIDC | `@semantic-release/npm` must not publish until explicitly enabled. |

## STRIDE register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-4-01 | Tampering | unauthorized npm publish | mitigate | `npmPublish: false` or equivalent in `.releaserc.json` for Phase 1 dry-run; publish only in gated environment later. |
| T-4-02 | Information disclosure | NPM_TOKEN in workflow | mitigate | Do not add long-lived NPM_TOKEN to workflow YAML; prefer OIDC when publish is enabled. |
| T-4-03 | Spoofing | wrong branch releasing | mitigate | `branches: ["main"]` only in semantic-release config; CI trigger on `push: main` only. |
| T-4-04 | Denial of service | duplicate release jobs | mitigate | Single workflow job; avoid PR triggers per D-06. |
| T-4-05 | Repudiation | missing changelog | mitigate | Changelog plugin in config per PRD §2.4 (dry-run still validates plugin graph). |
</threat_model>
